# Flashing, backup and recovery

## Back up the factory firmware first

Not optional. The board holds **32 KB of encoder calibration specific to your
motor**, generated by the factory calibration routine and present in no
published binary. It lives at `0x08018000` — above 64 KB — so a 64 KB dump
misses it entirely and leaves you with a backup that looks fine and is useless.

Dump the full **128 KB**:

```
openocd -f interface/stlink-hla.cfg -f target/stm32f1x.cfg \
  -c "init; reset halt" \
  -c "dump_image factory_128k.bin 0x08000000 0x20000" \
  -c "exit"
```

Verify it is real before trusting it. A good dump has:

- initial MSP in SRAM (`0x2000xxxx`) at offset 0 and a reset vector in flash
  (`0x0800xxxx`) at offset 4 — and these should match the `msp` and `pc` the
  core reports when halted
- programmed data at `0x08017C00` (settings) and `0x08018000` (calibration)
- many distinct byte values; a near-uniform dump means readout protection

## Wiring an ST-Link

Three wires to header P7:

| ST-Link | | Board |
|---|---|---|
| `SWCLK` | to | `SWCK` |
| `SWDIO` | to | `SWDO` |
| `GND` | to | `GND` |

Go by the **silkscreen labels**, not pin position — on the S57B the 3.3 V pin
sits *between* SWCK and SWDO, which is not the order you would guess.

**Leave the probe 3.3 V disconnected** and power the board normally from VIM.
The board regulates its own 3.3 V, so tying the probe output onto a live
regulator puts two sources against each other. The alternative is the reverse:
probe 3.3 V connected and VIM off, which is enough to flash and makes it
impossible for the motor to move. Never both at once.

SWD survives under the factory firmware, which calls
`GPIO_Remap_SWJ_JTAGDisable` (JTAG off, SW-DP kept), so connect-under-reset is
not needed.

## If your probe is a clone

Most cheap ST-Link V2 units are, and they work fine with two caveats.

**Use `interface/stlink-hla.cfg`.** Older clone firmware such as V2J17 speaks
only the deprecated HLA protocol. Plain `stlink.cfg` auto-selects dapdirect SWD
and fails with `Debug adapter doesn't support` or an init error.

**Never let any ST tool upgrade the ST-Link firmware.** OpenOCD will suggest it
on every run. Don't — it is the classic way to brick a clone. OpenOCD itself
never does this.

On Windows, OpenOCD talks libusb, so the probe needs a WinUSB-class driver. If
Device Manager shows error code 28, use [Zadig](https://zadig.akeo.ie):
Options, then List All Devices, select the ST-Link, choose **WinUSB**, Install.

A clone reported target voltage often wanders — 3.0 V, 3.7 V, 3.8 V across
consecutive runs — because its VTARGET sense pin floats. Ignore the number; it
is not diagnostic.

## Flashing

```
pio run -e s57b -t upload        # or -e s42b
```

This firmware is around 30 KB and sits below `0x08005000`. A normal `program`
cycle does **sector erase only**, so the factory calibration at `0x08018000`
survives — verified byte-identical before and after. It is lost only to an
explicit `stm32f1x mass_erase`, which this project never issues.

## Recovery

Restore your own dump:

```
openocd -f interface/stlink-hla.cfg -f target/stm32f1x.cfg \
  -c "program factory_128k.bin 0x08000000 verify reset; shutdown"
```

If you skipped the backup, BIGTREETECH publish a firmware binary in their
`BIGTREETECH-Stepper-Motor-Driver` repository under `S42B/firmware/`. It will
restore function but **not your motor calibration**, which must then be
regenerated with the on-board calibration routine.

## Troubleshooting

**"unable to connect to the target" with an otherwise healthy probe.** Check
the motor power supply. The STM32 is powered from VIM, so no motor supply means
no debug port. This is the single most common cause and costs more time than
anything else on this board.

**Coil A produces no torque.** PB4 is `NJTRST` and is a JTAG pin out of reset.
Without the SWJ NOJTAG remap it cannot drive PWM at all. This firmware does it
first thing in `setup()`.
